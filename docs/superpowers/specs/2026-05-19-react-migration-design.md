# Compound — React + Vite + TypeScript + Tailwind Migration

**Date:** 2026-05-19  
**Status:** Approved — ready for implementation planning

---

## Overview

Migrate Compound from a single `index.html` file (~6,000 lines of CDN React + `El()` factory) to a proper Vite + React + TypeScript + Tailwind project. The migration is motivated by layout limitations (no media queries with inline styles, unsafe DOM reordering at file size), not logic changes. All localStorage key names and data shapes are preserved exactly — the migration must be data-compatible with existing users.

---

## Decisions

| Concern | Decision | Rationale |
|---|---|---|
| Language | TypeScript | Type safety during refactor; catches prop mismatches when splitting App |
| Strategy | Big bang | App is already React; El()→JSX is mechanical; incremental would require duplicating state layer |
| CSS | Tailwind | Layout features (side-by-side Expenses, mobile) require media queries — impossible with inline styles |
| State | React Context | One global data object maps perfectly to one Context; zero new dependencies |
| Decomposition | Tab + card-level (Option B) | Tab files as primary split; card-level components extracted where they appear |

## Context / State Layer

### DataContext

`src/context/DataContext.tsx` provides:

- `data: AppData` — full persisted state, same shape as `compound_v4`
- `setData: (updater: (prev: AppData) => AppData) => void` — functional updater; persists to `compound_v4` on every call
- `useData()` — convenience hook; throws if used outside provider

`migrateData` runs once inside the `useState` initializer on first load. localStorage write happens inside `setData`, not in `useEffect` — this matches the existing pattern and avoids a render cycle.

### UIContext

`src/context/UIContext.tsx` provides ephemeral UI state that does not belong in the persisted data model:

- `activeTab: TabId` — current active tab
- `showSuggestions: boolean` — discretionary category suggestions dropdown
- `importMessage: string` — import/export status message

Tab components use `useData()` and `useUI()` directly — no prop drilling anywhere.

### localStorage Keys (invariant — must never change)

| Key | Owner | Purpose |
|---|---|---|
| `compound_v4` | `DataContext` | Full app data |
| `compound_onboarding_done` | `WelcomeModal` / `QuickStart` | Onboarding completion flag |
| `compound_profile_done` | Profile card component | Profile card dismissed flag |

`STORAGE_KEY = "compound_v4"` is defined once in `lib/storage.ts` and imported everywhere. Never inlined as a string literal.

## Migration Sequence

Execute in this order to minimize risk. Each step produces a runnable app.

### Step 1 — Scaffold (no content yet)
- Rename `index.html` → `index.legacy.html`
- `npm create vite@latest . -- --template react-ts`
- Install: `tailwindcss`, `@tailwindcss/vite` (or `postcss`/`autoprefixer`)
- Configure `tailwind.config.ts` with custom tokens
- Wire `src/index.css` with Tailwind directives
- `App.tsx` renders a placeholder `<div>` per tab
- **Checkpoint:** `npm run dev` boots with blank dark background

### Step 2 — Lib layer (pure functions, no React)
- Copy `migrateData`, `makeDefault` → `lib/storage.ts`; add types
- Copy `fmt`, `fmtDec`, `fmtCurrencyInput` → `lib/format.ts`; add types
- Copy all calculation functions (DTI, savings rate, payoff) → `lib/calculations.ts`; add types
- **Checkpoint:** TypeScript compiles with no errors

### Step 3 — Types
- Define all interfaces in `src/types/index.ts` per the spec above
- **Checkpoint:** Types import cleanly into lib files

### Step 4 — Context layer
- Implement `DataContext.tsx` with localStorage load + `migrateData` on init, `setData` persists on every call
- Implement `UIContext.tsx` with `activeTab`, `showSuggestions`, `importMessage`
- Wire both providers in `main.tsx`
- **Checkpoint:** `useData()` and `useUI()` return correct initial values in browser devtools

### Step 5 — Shared components
Convert in order (simplest first):
`Input → SectionTitle → Card → Badge → LineChart`

`RowHeader` is used only inside `BudgetRow` — keep it as a local component there, not promoted to `components/`.

Each: copy from `index.legacy.html`, convert `El()` → JSX, replace inline styles with Tailwind classes, add TypeScript props interface.

### Step 6 — Tabs (simplest → most complex)
`Settings → Overview → Income → Expenses → Savings → Invest & Retire → Plan`

For each tab:
1. Copy the relevant section of `App()` from `index.legacy.html` into the tab file
2. Convert `El()` → JSX
3. Replace inline styles with Tailwind
4. Extract Option B card components (`DebtCard`, `IncomeSourceCard`, `SavingsCard`, `MortgageCard`) as they appear
5. Wire to `useData()` / `useUI()`
6. Import tab into `App.tsx`, replace placeholder

**Checkpoint after each tab:** tab renders correctly in browser, data reads/writes to localStorage correctly.

### Step 7 — Onboarding
- Migrate `WelcomeModal` and `QuickStart` wizard last
- These read/write `compound_onboarding_done` directly — preserve exactly
- **Checkpoint:** Full onboarding flow works end-to-end with fresh localStorage

### Step 8 — Final cleanup
- Delete `index.legacy.html`
- Add `dist/` to `.gitignore`
- Run `npm run build` and verify output
- Update `claude.md` to reflect new stack

## Invariants (must never be violated)

- localStorage keys `compound_v4`, `compound_onboarding_done`, `compound_profile_done` are never renamed
- `migrateData` function is never removed — it handles backward compat for existing users
- All currency/numeric fields remain typed as `string` in the data model
- No new features added during migration — this is infrastructure only
